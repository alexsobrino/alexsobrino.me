# Content language lives in each Note, not in the URL

The site starts in Spanish and may later switch to English, but it will not be a bilingual site with translated pairs. So each Note and Side Project records its own content language, URLs have no language prefix (no `/es/` or `/en/`), and the site's own text (navigation, headings) is in one language at a time. Switching to English means writing new content in English and changing the site's text; existing Spanish Notes keep their URLs. We rejected an `/es/` prefix from day one because it adds weight to every URL for a bilingual future that isn't planned. We rejected Spanish at the root with `/en/` added later because Spanish would stay the default even after English takes over. For the same reason, path names are in English (`/notes/`, `/side-projects/`) even while the site's text is Spanish, so they still fit after the switch; only each item's slug follows its content language. Don't add i18n routing unless translated pairs become a real requirement.
